feat(audit): 加 measure audit，一次会话跑完计划里的全部测量

## 解决的问题

每个 measure 子命令都要起进程、加载 puppeteer、连 CDP、等页面。
实测一次真实审计（令牌 + 样式 + 命中数 + 盒模型 + 对比度）分成 5 次调用：

  5.9 秒 / 5 次工具调用

其中每次约 1.2 秒是固定的进程与连接开销，与测量本身无关。
对 agent 是双重代价：既是时间，也是上下文轮次。

一次 audit 后：

  1.16 秒 / 1 次调用        提速 5.1 倍

## 形状：对齐 pa11y 的 config 约定

查了三个社区项目：
- Lighthouse 用 config 对象 + extends 预设体系
- pa11y 用 --config <path> + 默认文件名自动发现，且写明优先级规则
- Playwright 是 commander 子命令树，没有批量化入口

选 pa11y 因为它对 agent 最直接：写一份 JSON、跑一条命令。

约定：
- 缺省读 ./.siyuan-audit.json（也接受 .js / .mjs，走模块加载）
- --config <path> 覆盖；显式指定却不存在时**报错**而不是静默退回
- 优先级：命令行参数 > 配置文件 > 内置默认值
- 命令行传了的字段**整体替换**文件里的同名字段，不追加（语义可预测）

## 计划能表达什么

tokens / styles / counts / boxes / probes / contrast / diffs，
外加 setup（建立场景）与 actions（测量前动作）。

styles 与 boxes 支持简写（选择器字符串）与对象形式（带自己的 props / limit）。

## 校验在建会话之前

计划是给人/agent 写的 JSON。写错了如果在浏览器里才发现，每次白起一个会话。
validatePlan() 在 createSession() 之前跑完，空计划也提前拒绝。

## 实测

- 5 次子命令 5.9s -> 1 次 audit 1.16s（5.1x）
- setup 有效：--setup "contextmenu:.b3-list-item" 后 .b3-menu__item 从
  「未找到元素」变成量到 14 个真实菜单项
- 配置文件自动发现生效，contrast 正确算出 15.02:1 与 5.6:1
- 包内测试 71 -> 79；pnpm check 全绿

## 顺带

skill 与 README 都加了「多项一起量优先用 audit」的指引，
并说明 setup 的必要性（菜单项在打开前不在 DOM 里）。
