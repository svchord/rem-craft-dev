## 为什么是目录分层而不是拆包

实测两个方案的保护强度，都是「靠约定」而非「靠编译器」：

- 单包时让 core 层 import vite -> tsc exit 0（没拦住）
- 拆包后 core 包不声明 vite 却 import 它 -> tsc exit 0（也没拦住）

原因：pnpm workspace 里 packages/*/node_modules/vite 是指向根 .pnpm 的 junction，
子包没有独立 .pnpm，模块解析一路向上找得到根 node_modules。
所以拆包并不能阻止越界 import，它只让 package.json 的依赖声明更准确。

真正的保护来自架构测试——这个已经有了。所以把断言从「正则扫扁平文件清单」
升级成「按目录收集 + 检查依赖方向」，新增文件自动纳入，不会因漏加清单而漏检。

## 结构

  core/    14 文件  被测对象契约与测量原语，不依赖 vite、无 bin、不碰 process.exit
  dev/      3 文件  两种形态共用的开发链路
  plugin/   2 文件  依赖 vite 的插件形态
  cli/      7 文件  命令行入口，不实现 vite 插件钩子
  index.ts          顶层唯一文件，聚合导出

## 新增的架构测试

- keeps every source file inside a layer   顶层不得有游离 .ts，四层不得为空
- keeps core free of vite, bin and dev-loop concerns
- keeps plugin free of cli concerns
- keeps cli free of vite plugin hooks

既有断言里 9 处硬编码了同层路径（from './targets.ts'），改为只关心文件名，
跨层移动不再误报。

## 顺带修掉

build 脚本原本不清理 dist，目录重组后会残留旧路径的编译产物
（实测 dist 顶层留下 28 个旧 .js）。加 clean 步骤。
