refactor(pkg): 清理架构冗余，package.zip 收为固定产物名

## 1. package.zip 不再作为入参

用户指出这是思源规定的产物命名。核实三处证据一致：
  主题项目 .releaserc.json 的 assets 指向 package.zip
  插件项目 vite.config 的 outFileName 是 package.zip
  思源官方 sample 同样是 package.zip

所以它是集市约定，不是项目发布偏好。我上次把它判断成「项目决策」是错的，
.releaserc.json 只是消费这个约定，不是定义它。

改动：
  post.ts 导出 PACKAGE_NAME = 'package.zip'
  删除 PackOptions 接口、resolvePack() 归一化
  pack 从 boolean | PackOptions 简化为 boolean
  父项目 pack: { outFile: ... } -> pack: true

## 2. 修注册表破口（最严重）

之前两处硬编码清单名，让「注册第三种类型就能用」的承诺失效：
  plugin.ts  public/${requestedKind === 'plugin' ? 'plugin.json' : 'theme.json'}
  assets.ts  manifestPath 缺省 'public/theme.json'

现在都从 descriptor.manifestName() 取：
  plugin.ts 新增 manifestFile()，用 targetType(kind).descriptor.manifestName()
  assets.ts manifestPath 改为必需参数，由调用方传入

注册 widget 后资产插件会自动去找 widget.json。

## 3. 收敛 resolveTarget()

「target/kind 入参 -> 类型名 -> 描述符 -> Target」这段逻辑之前在
config()、ensureSession()、post 的 resolveTarget 各写一遍，加类型要改三处。
现在统一成 resolveTarget()，失败时带出 reason，不再为拿错误原因二次调用
detectTargetType。detectTargetType 出现次数 4 -> 2。

## 4. 删 REQUIRED_CAPABILITIES 运行时校验

那份 9 项能力清单和 TargetDescriptor 接口是同一份知识的两种写法，
改接口时容易漏改。TS 项目里靠 satisfies TargetDescriptor 编译期约束即可。
测试改为验证「注册表不再挑剔，满足接口的自定义类型能注册」。

## 5. 修 verify.ts 文件列表不一致

之前 expectedFiles 检查用递归 walk()（相对路径），VerifyContext.files 用
顶层 readdirSync()（只文件名）——两次遍历、两套语义。现在一次 walk()
供两处共用，readOutput 也提到同一处。顺带把 outDir.startsWith(root)
换成 isAbsolute()（前者有 /foo vs /foobar 误判）。
