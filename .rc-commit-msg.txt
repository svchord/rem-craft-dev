feat(devtools): 统一 CLI、可扩展类型注册表、与构建工具解耦

三个问题一起解决，因为它们本质上是同一件事：包要能独立工作。

1) 一个命令，不用在引用项目里写脚本
   siyuan-devtools dev / link / measure / open / watch
   旧的 siyuan-measure 等仍保留为等价独立命令。
   实测：新建一个只有 public/theme.json 的空项目，不写任何 scripts，
   直接跑 CLI 就能正确推断类型并定位安装目录。

2) 类型可扩展，不再写死 theme/plugin
   新增 target-types.mjs：被测类型 = 一份能力描述符（清单名、安装子目录、
   环境变量名、产物名、重载方式、CSS 来源、挂载判定），注册即生效。
   dev.mjs 里已无任何 kind === 'theme' 分支，这条约束由测试钉住。
   注册时缺能力会直接拒绝并列出缺哪几个，避免 dev.mjs 长出类型分支。
   内置 theme/plugin 各带 detect，从 public/ 清单自动推断。

3) 与 vite / vitest 解耦
   vite 不再出现在任何 dependencies/peerDependencies 里。构建驱动改为可插拔：
   默认仍是 vite build --watch（思源项目最常见），但 --build-command 可换成
   任何命令。实测用 node -e 模拟的 watcher 跑通了完整 dev 循环。
   puppeteer-core 从 peerDep 改为真正的 dependency——它是运行时必需，
   不该让引用项目操心装哪个版本。

同时修掉一个真实 bug：插件描述符的 reload 依赖 this.resolveCss()，
重构后 this 绑不上，热重载静默失效（日志只有一行 resolveCss is not a function）。
改为 createTarget 预先绑定 resolveCss 放进 context，并补测试钉住。

根 scripts 从 6 个降到 4 个：dev-live.mjs 与 make_dev_link.js 已由 CLI 取代。
测试 49 -> 51，含类型注册表扩展性、自动推断、构建驱动切换。
