## 删掉 enabled，开发/生产由 build.watch 判断

实测五种写法都能在 config() 与 configResolved() 里拿到一致结果：

  --watch            build.watch={}     -> true
  -w                 build.watch={}     -> true
  config 写 watch:{} build.watch={}     -> true
  config 写 watch:true build.watch=true -> true
  都不写             build.watch=undefined -> false

Vite 自己已经把命令行归一化进 build.watch，项目再传一个 isWatch 只是
重复同一件事，还多一处可能不一致的输入。父项目删掉 enabled 一行。

## 产物校验（verify，缺省开）

思源的失败模式是静默的，和 Electron 生态根本不同：Electron 产物指错地方会
启动崩溃、报错可见；思源则什么都不显示。已收进包的规则：

  通用（core/verify.ts）
    清单存在、必需字段、version 是 semver
    清单与 package.json 版本一致  -> 不一致时集市判为旧版、不推送更新
    i18n 字段带 default 项
    产物含 expectedFiles
  主题特有（描述符）
    modes 非空且只有 light/dark
    产物不允许 .js
    CSS 不允许 @layer（会被 base.css 压制）
  插件特有（描述符，对照 arco-calendar 的 check_manifest.mjs）
    minAppVersion 必须是 semver
    public/i18n 存在且含 en.json、zh-CN.json，key 集合一致

规则来源是现有两个项目的脚本，逐条搬过来。

## 两个环境都校验，失败处理不同

  开发（watch）  警告并继续——中断会让 vite build --watch 退出，得手动重开
  生产（build）  中断构建——产物要发布，坏包代价远大于构建失败

## 收尾插件用 enforce: 'post'

实测 Vite 的 writeBundle 按 enforce 分三段执行：
  pre-d -> plain-a -> plain-c -> post-b -> post-e

所以 post 能保证看到完整产物，且校验抛错时不会往下走到打包。

## 打包（pack，缺省关）

自己用 node:zlib 写 zip（store/deflate 双策略），零依赖。
只在非 watch 执行，且在校验通过之后。包名由项目给（package.zip 是
.releaserc.json 的约定，不是思源约定）。
